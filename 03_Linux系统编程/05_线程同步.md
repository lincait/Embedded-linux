# 线程同步

## 竞态条件和锁

### 竞态条件

- 多个线程并发访问并修改同一个共享资源（如全局变量）时，如果没有同步措施，最终结果依赖线程执行的具体时序，这就是竞态条件。
- 例如用20000个线程对同一个变量累加，结果不确定且小于20000。原因是从代码上看是`(*p)++`，实际执行会分成读取、加一、写回多个步骤，线程之间可能交错执行，导致多次累加只生效一次。
- 避免竞态条件有两种思路：避免多线程写入同一个地址；给共享资源加锁，使同一时间只有一个线程操作特定资源。

### 常见锁机制

锁就相当于一扇上锁的门，线程想要通过这扇门执行后面的代码（临界区代码）必须要获取锁。但是锁机制只是软件上的约束，必须要在程序上写好开锁解锁才能实现同步。

联合体`pthread_mutex_t`就相当于门（锁本身），`lock`函数就相当于开门这个动作。所有线程都可以看到这门也都可以去尝试开门（开锁），但同一时间只有一个线程可以通过这个门，只有这个线程出来（`unlock`）之后其他线程才能通过门。

- 互斥锁（Mutex）：保证同一时刻只有一个线程能执行临界区代码。
- 读写锁（Reader/Writer Locks）：允许多个读线程同时读共享数据，写线程之间互斥。
- 自旋锁（Spinlocks）：获取锁之前循环忙等待，适合锁持有时间非常短的场景，一般由Linux内核使用。

## 互斥锁

### pthread_mutex_t

- `pthread_mutex_t`是定义在`pthreadtypes.h`中的联合体类型的别名。
- 互斥锁用于控制共享资源访问，任何时刻最多只有一个线程持有某把锁。
- 若线程请求的锁已经被占用，则请求会被阻塞，直到锁被释放。
- 用途：保护共享数据，避免多个线程同时访问导致数据不一致；实现线程间访问顺序。

### 互斥锁操作函数

```c
int pthread_mutex_init(pthread_mutex_t *restrict mutex, const pthread_mutexattr_t *restrict attr);
```

初始化互斥锁，`attr`传`NULL`使用默认属性。

```c
int pthread_mutex_lock(pthread_mutex_t *mutex);
```

阻塞式获取锁，锁被占用时等待；成功返回0，失败返回错误码。这个函数相当于在尝试开锁，线程如果调用了这个函数，那就必须等待获取到锁时才会运行后面的代码。

```c
int pthread_mutex_trylock(pthread_mutex_t *mutex);
```

非阻塞式获取锁，锁被占用时立即返回`EBUSY`，不会阻塞。通常要根据返回值来确定后续代码的分支，如果不判断那就跟没上锁一样。

```c
int pthread_mutex_unlock(pthread_mutex_t *mutex);
```

释放锁，调用线程必须是当前持有锁的线程；释放后其他线程可以获取锁

```c
int pthread_mutex_destroy(pthread_mutex_t *mutex);
```

销毁锁，清理资源。
- `PTHREAD_MUTEX_INITIALIZER`用于静态初始化，例如`static pthread_mutex_t counter_mutex = PTHREAD_MUTEX_INITIALIZER;`。它会将锁设置为默认属性和未锁定状态，不需要调用初始化函数，适合全局或静态变量。
- 使用**流程**是修改共享变量前加锁，修改完成后解锁。
- 静态初始化的锁在程序即将结束时可以不显式销毁，进程退出时操作系统会回收资源；动态初始化或锁需要跨多个函数、文件使用时，不再需要时应显式销毁。

## 读写锁

### 工作原理

- 多个线程可以同时持有读锁，并发的读数据；读锁和写锁互斥，即有一个线程获取了读锁，其他尝试获取写锁的线程就会被阻塞；同一时刻只能有一个线程获取写锁。（**读读共享，读写互斥，写写互斥**）
- 读写锁默认策略是读优先。读操作远多于写操作时，读线程不断获得读锁，写线程可能长时间无法获得写锁，这就是写饥饿。
- 解决写饥饿要把读写锁属性设置为写优先：`PTHREAD_RWLOCK_PREFER_WRITER_NONRECURSIVE_NP`。`PTHREAD_RWLOCK_PREFER_WRITER_NP`在glibc中会被忽略。
- 线程执行顺序由内核调度决定，先创建的线程不保证先执行。

### 相关调用

```c
int pthread_rwlock_init(pthread_rwlock_t *restrict rwlock, const pthread_rwlockattr_t *restrict attr);
```

```c
int pthread_rwlock_rdlock(pthread_rwlock_t *rwlock);
```

获取读锁，写锁被持有时阻塞。

```c
int pthread_rwlock_wrlock(pthread_rwlock_t *rwlock);
```

获取写锁，只要任意线程持有读写锁就阻塞。

```c
int pthread_rwlock_unlock(pthread_rwlock_t *rwlock);
```

释放调用线程持有的锁。

```c
int pthread_rwlock_destroy(pthread_rwlock_t *rwlock);
```

- `pthread_rwlock_t`与互斥锁中的结构体类似，也是联合体类型的别名，`attr`传`NULL`时使用默认属性，也可以用`PTHREAD_RWLOCK_INITIALIZER`静态初始化。

- 设置写优先的流程：

  ```c
  pthread_rwlockattr_init(&attr);	// 初始化属性对象
  
  // 设置为写优先
  pthread_rwlockattr_setkind_np(&attr, PTHREAD_RWLOCK_PREFER_WRITER_NONRECURSIVE_NP);
  pthread_rwlock_init(&rwlock, &attr);	// 用该属性初始化读写锁
  ......
  pthread_rwlockattr_destroy(&attr);	// 最后销毁属性对象	
  ```

- `pthread_rwlockattr_init`和`pthread_rwlockattr_destroy`分别初始化和销毁读写锁属性对象。
- 设置写优先后再运行测试，写操作可以插在连续读操作之间，写饥饿得到解决。

## 自旋锁

- 自旋锁在锁被占用时持续循环检查锁状态，而不是让线程休眠，因此省去了线程上下文切换的开销。
- 适合锁持有时间非常短的场景，主要用于Linux内核模块或驱动中，不能在用户空间使用。

## 条件变量

### 线程间条件切换函数

- 条件变量相当于提供了一种线程间的通信机制，但必须和互斥锁配合使用，保证共享资源访问互斥，同时避免竞态条件。
- `pthread_cond_t`是联合体类型的别名，它定义的即为条件变量，通过`pthread_cond_init`初始化。不同的线程就通过同一个条件变量来互相唤醒或被唤醒。
- `PTHREAD_COND_INITIALIZER`也可以静态初始化全局或静态条件变量，不再需要时用`pthread_cond_destroy`清理。
```c
int pthread_cond_wait(pthread_cond_t *restrict cond, pthread_mutex_t *restrict mutex);
```

调用它的线程必须已经持有`mutex`，调用后线程临时释放`mutex`并阻塞，被唤醒后再重新获取`mutex`，获取后从下一行代码开始。
作用是在某个线程持有锁的期间也可以暂时释放锁交给其他线程。

```c
int pthread_cond_timedwait(pthread_cond_t *restrict cond, pthread_mutex_t *restrict mutex, const struct timespec *restrict abstime);
```

带超时的阻塞等待，`abstime`是绝对时间，超时返回`ETIMEDOUT`。

```c
int pthread_cond_signal(pthread_cond_t *cond);
```

唤醒至少一个等待该条件变量的线程（一般是唤醒其他线程），没有线程等待时什么都不做。

```c
int pthread_cond_broadcast(pthread_cond_t *cond);
```

唤醒所有等待该条件变量的线程。

### restrict关键字

- `restrict`是C99引入的关键字，修饰指针时表示该指针是作用域内访问所指向对象的唯一方式。
- 它给编译器提供优化依据，如果程序违反这个约定，行为未定义。

### 生产者消费者模型

- 典型用法：生产者对缓冲区写数据，消费者读数据。实现数据一次写满再一次性读出

- 实现流程：

  ```c
  // 生产者
  pthread_mutex_lock(&mutex);	// 获取锁
  while(1)
  {
      while( 缓冲区写满 )
      {
          pthread_cond_signal(&cond);		// 唤醒消费者
          pthread_cond_wait(&cond, &mutex);	// 暂停线程，把锁暂时交出
  	}
      
      逐个写数据;
  }
  pthread_mutex_unlock(&mutex);	// 释放锁
  ```

  ```c
  // 消费者
  pthread_mutex_lock(&mutex);	// 获取锁
  while(1)
  {
      while( 缓冲区为空 )
      {
          pthread_cond_signal(&cond);		// 唤醒生产者
          pthread_cond_wait(&cond, &mutex);	// 暂停线程，把锁暂时交出
  	}
      
      逐个读数据;
  }
  pthread_mutex_unlock(&mutex);	// 释放锁
  ```

- 例程中生产者和消费者共用互斥锁和条件变量：生产者持锁检查缓冲区是否满，满则唤醒消费者并暂停线程，不满则写入；消费者相反。

- 检查条件用`while`而不是`if`，因为线程被唤醒后条件可能仍然不满足，需要重新检查。
