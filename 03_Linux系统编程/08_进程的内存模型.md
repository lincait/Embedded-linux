# 进程的内存模型

## 内存布局

一个进程在内存中的布局如下：

```text
高地址
+---------------------------+
|         内核空间            |  ← 存放内核代码和数据，用户程序不可见
+---------------------------+
|     用户栈（向下增长 ↓）     |  ← 局部变量、函数调用信息
|           |               |
|           ↓               |
|     内存映射区（共享库等）   |
|           ↑               |
|           |               |
|      堆（向上增长 ↑）       |  ← malloc动态分配的内存
+---------------------------+
|     数据段（.data/.bss）    |  ← 全局变量、静态变量
|     代码段（.text）         |  ← 程序的机器码
+---------------------------+
低地址
```

- 从低地址到高地址依次是：代码段、数据段、堆、内存映射区、用户栈，最顶部是内核空间。
- 栈和堆相向生长，二者之间隔着内存映射区，这是为了防止栈和堆增长时互相覆盖。

## 相关概念

### 栈

- 栈（Stack）是FILO（First In Last Out）即先进后出类型的数据结构。
- 进程的内存模型里有一块区域作为用户栈，最先进入的数据位于**栈底**，最后进入的数据位于**栈顶**。

### 栈帧

- 栈帧（Stack Frame）是程序在调用函数时用于存储函数调用和局部变量的一块内存。
- 每次函数调用时，都会在调用者的栈上创建一个新的栈帧。栈帧包含函数的返回地址、参数、局部变量以及保存的必要寄存器值。
- 每个栈帧对应一个函数调用的上下文，它是程序运行时栈内存组织的基本单元。栈帧让函数调用彼此隔离，同时支持递归调用和嵌套调用。
- 调用函数时，会在栈顶为函数分配一帧，然后移动栈指针指向新的栈顶，称为**压栈**；函数调用结束（返回）时，释放函数的栈帧，称为**弹栈**。
- 理解：栈帧像每个函数的一张"工作台"，函数调用就像在原有工作台上再架一层新工作台，返回时拆掉这一层。递归就是一层层叠上去再一层层拆下来。

### 栈指针

- 栈指针（Stack Pointer，SP）是专用寄存器，用于记录栈顶位置。

### 帧指针

- 帧指针（Frame Pointer，FP，有些架构中也叫Base Pointer，BP）是专用寄存器，用于记录调用者栈帧的位置。
- 理解：栈指针跟着栈顶走（当前函数随时可能压栈弹栈），帧指针则钉住当前函数栈帧的起点，函数通过它加偏移量来访问自己的参数和局部变量。

### 内核空间

- 内核空间是进程虚拟内存中保留给操作系统内核的部分，用于存放内核代码和数据。
- 这部分空间对用户程序不可见、不可直接访问，具有最高的访问权限，只有内核态下的代码可以执行这里的操作。
- **所有进程的内核空间是共享的**。

### 用户空间

- 用户空间是内存中分配给用户程序的部分，与内核空间相隔离，用户程序和库函数在这里执行。
- 用户空间的代码运行在用户态，拥有较低权限，不能直接执行特权操作或访问内核空间。
- 理解：内核空间像公司的"管理区"，用户空间像"员工区"。员工不能进管理区，但所有员工共享同一个管理区（所有进程共享同一份内核）。

# 虚拟内存和物理内存

## 一个看似矛盾的案例

写一个测试程序：`fork`创建子进程，子进程把变量`val`改成321，父进程休眠一秒后再打印自己的`val`。

```c
#include <stdio.h>
#include <unistd.h>
int main() {
    int val = 123;
    __pid_t pid;
    if ((pid = fork()) > 0 ){
        sleep(1);
        printf("父进程中val 的内容是: %d\nval 所在的地址是: %p\n", val, &val);
    } else if (pid == 0) {
        val = 321;
        printf("子进程中val 的内容是: %d\nval 所在的地址是: %p\n", val, &val);
    } else {
        printf("子进程创建失败\n");
    }
    return 0;
}
```

- 运行结果：父子进程打印出的`val`**地址完全相同**，但子进程把`val`改成321后父进程的`val`不受影响，仍是123。
- 既然地址相同，两个`val`不应该是同一个变量吗？可为什么修改互不影响？这不矛盾吗？
- 要明白这个问题，需要了解操作系统的**虚拟内存机制**。

## 虚拟内存映射

### 知识储备

- **虚拟内存**：一种内存管理技术，为每个进程提供"虚拟"的地址空间。这个地址空间对每个程序来说看起来是连续的，但实际上可能被分散存储在物理内存和磁盘上（如交换空间或页面文件）。虚拟内存允许系统**超额分配内存**（分配的总量可以超过物理内存实际容量），并且让应用程序不需要关心物理内存的实际情况。
- **物理内存**：计算机中安装的实际RAM（随机访问存储器）模块，是系统存储正在运行的程序和数据的硬件资源。
- **MMU**：Memory Management Unit，CPU的一个组成部分，负责处理虚拟地址到物理地址的转换。程序访问虚拟内存地址时，MMU查询页表找到对应的物理内存地址，完成内存访问。MMU还负责检查访问权限，防止程序访问未授权的内存区域。当所请求的虚拟地址没有映射到物理地址、或虚拟页对应的数据在磁盘交换空间中时，会产生**缺页故障**，MMU通知操作系统，由操作系统为虚拟页分配页帧，或把数据从硬盘加载到内存，然后更新页表建立新映射，程序再次访问时就能正确访问。
- **页**（Page）：虚拟内存管理的基本单位，通常大小为4KB或2MB，具体取决于处理器和操作系统的设计。
- **页帧**（Page Frame）：也叫物理页，是物理内存中固定大小的区块。物理内存被划分为许多大小相等的页帧，便于内存的管理和映射。
- **页表**：用于管理虚拟地址到物理地址映射的数据结构。页表包含页表项（Page Table Entries，PTEs），每个PTE对应一个页，包含该页映射到的页帧的物理地址及访问该页的权限和状态（如是否在物理内存中、是否可写）。在x86-64架构下，页表大小为4K。
- **TLB**：Translation-Lookaside Buffer，地址转换旁路缓存。是MMU的组成部分，是硬件为提升虚拟地址到物理内存地址映射的效率而提供的硬件支持。
- **多级页表**：32位系统中每个进程的虚拟地址空间为4GB，假设页大小4KB，则一个进程的虚拟地址空间要分为1M页，假定每个PTE为4字节，每个进程就要占用4MB空间存储页表。启动100个进程，仅页表就要占用400MB内存，而很少有进程会用完所有虚拟页，浪费巨大。为了解决这个问题引入多级页表（此处不做展开），多级页表中除最后一级外都可以叫做页目录（Page Directory）。

理解：
- 虚拟内存就像给每个进程发了一张"虚拟城市地图"，地图上街道看起来连续完整；MMU是"导航员"，负责把地图上的位置翻译成真实的街道（物理地址）。
- 页表就像"翻译词典"，TLB是"最近查过的词条小抄"——查过一次的翻译直接记在小抄上，下次不用再翻词典。
- 多级页表像"目录套目录"，先查大目录再查小目录，避免为用不到的页面浪费整本词典。

### 回到案例

- 父子进程打印的地址相同，是因为它们打印的是**虚拟地址**，各自的地图上都写着同一个地址。
- 但在各自的页表里，这个虚拟地址可以映射到**不同的物理页帧**（子进程修改`val`时触发了写时拷贝，见11笔记），所以修改互不影响。
- 地址相同只是"门牌号相同"，实际住的"房子"（物理内存）不是同一间。

## 再看进程共享存储

有了虚拟内存的知识，回头看03笔记的共享内存实现，整个过程分两步：

1. 通过`shm_open`创建内存共享对象。这一步实际上是内核创建了一个**匿名文件**，它不与文件系统的具体文件直接关联，只是存在于内核的一个对象，内存共享对象通过文件名来唯一标识。
2. 通过`mmap()`将进程的虚拟内存映射到上一步的共享对象。当多个进程映射到相同的共享对象时，内核根据后者的文件名确定这一点，并将多个进程的虚拟内存映射到**相同的物理内存**，这样就实现了进程间内存共享。

- 本质就是：多个进程的页表里，各自的虚拟页都指向同一个物理页帧。普通的内存是"一进一出"，共享内存是"多进一出"。
