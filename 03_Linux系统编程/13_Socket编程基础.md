# Socket 编程基础

网络编程的最终目的，是让运行在不同主机上的进程通过网络交换数据。但在写代码之前，先要理解网络本身是怎么组织的——这就是本节的背景知识。

# 计算机网络的分类

按地理范围划分：

- **个人区域网（PAN）**：几米到十几米，连接个人设备，如蓝牙、红外。
- **局域网（LAN）**：覆盖一个建筑物、办公室或校园，如以太网、Wi-Fi。
- **城域网（MAN）**：覆盖一个城市，连接多个局域网，如光纤网络。
- **广域网（WAN）**：覆盖国家、洲际甚至全球，如互联网。

# 网络分层模型

## 为什么要分层

网络通信是一个极其复杂的过程：数据要经过物理传输、寻址、路由、可靠传输等多个环节。分层就是把整个过程拆成若干层，每一层只关心一个特定方面（物理传输、路由、可靠性等），并为上一层提供服务。

分层的核心好处：**上层不用关心下层的实现细节**。每一层只需要知道自己怎么调用下一层、以及如何被上一层调用，就可以独立设计和升级。就像寄快递：寄件人不用关心包裹怎么上飞机、走哪条航线，只要把东西交到快递点（接口），剩下的由物流各环节负责。

## OSI 七层模型

国际标准化组织（ISO）在 1984 年提出，是学术和法律上的国际标准。自下而上：

- **物理层**：传输原始比特流，涉及电缆、电信号等物理介质。
- **数据链路层**：确保物理链路上的无误传输，提供帧同步、错误检测等功能。
- **网络层**：负责数据包从源到目的地的路由选择，定义了 IP 地址。
- **传输层**：提供端到端的传输服务，保证数据完整性，如 TCP、UDP。
- **会话层**：管理会话的建立、维持和终止。
- **表示层**：处理数据的表示、编码、加密等。
- **应用层**：为应用程序提供网络服务，如 HTTP、FTP、SMTP。

## 五层模型与 TCP/IP 四层模型

- **五层模型**：把 OSI 的应用层、表示层、会话层合并成应用层，其余不变，是教学常用的模型。
- **TCP/IP 四层模型**（互联网协议套件）：应用层、传输层、互联网层、链路层，是事实上的国际标准，现实中被广泛遵循。

以 TCP/IP 四层模型看各层职责：

- **应用层**：用户直接交互的部分，包含 SMTP、FTP、SSH、HTTP 等协议。
- **传输层**：管理端到端（主机到主机）通信。TCP 提供顺序、可靠、双向的连接流；UDP 提供无连接的数据报服务，不保证顺序和可靠。
- **互联网层**：跨网络路由数据包。核心是 IP 协议，它**不保证可靠性**，可能丢包。
- **链路层**：在物理网络上传输 IP 数据报，负责 MAC 地址寻址、帧同步、错误检测，如以太网、Wi-Fi。

> OSI 模型是"标准长什么样"，TCP/IP 模型是"现实长什么样"。

## 服务、协议和接口

这三个概念常被混淆，一句话区分：

- **服务**：下层能为相邻上层提供什么功能（"做什么"）。
- **接口**：上层怎么调用下层（"如何调用"）。
- **协议**：下层用什么规则实现这个功能（"如何实现"）。

接口是相邻层之间交互的规范，服务访问点（SAP）是接口中具体的逻辑位置，上层通过 SAP 访问下层服务。以传输层和网络层为例：传输层请求网络层"把数据包路由到目的地"（服务），通过 IP 协议栈的 API 提交数据包（接口），IP 协议定义了如何寻址、打包和路由（协议）。

## 网络传输中的数据单元

- **PDU**（协议数据单元）：对等层之间交换信息的数据单位。各层 PDU 有专门术语：链路层叫**帧**，网络层叫**数据包**，TCP 传输层叫**报文段**，UDP 的叫**数据报**。
- **SDU**（服务数据单元）：本层从上层接收到的原始数据，还没有加上本层的控制信息。
- **PCI**（协议控制信息）：本层添加的控制信息，包括地址、端口号、控制标志等。头部和尾部都属于 PCI。

关系：**PDU = SDU + PCI**。数据从上往下传输时，每经过一层就加上该层的头部，这个过程叫**封装**。这就是"寄快递"式的层层打包：内层包裹外面再套外层包装，每层包装上写自己这一层认识的标签。

# 网络字节序与主机字节序

字节序指多字节数据在内存中的存储顺序：

- **大端字节序（Big-Endian）**：高位字节存在低地址处，遵循自然数字书写习惯。网络协议（如 IP）要求使用大端，所以也叫**网络字节序**。
- **小端字节序（Little-Endian）**：低位字节存在低地址处。Intel x86-64 等处理器采用，也叫**主机字节序**。

不同主机字节序可能不同，因此网络传输前必须统一成网络字节序。发送方把主机字节序转成网络字节序，接收方再转回自己的主机字节序。 

## 字节序转换函数

头文件 `#include <arpa/inet.h>`：

```c
uint32_t htonl(uint32_t hostlong);
```

32 位主机字节序 → 网络字节序（h→n，l 为 long）。

```c
uint16_t htons(uint16_t hostshort);
```

16 位主机字节序 → 网络字节序（h→n，s 为 short）。

```c
uint32_t ntohl(uint32_t netlong);
```

32 位网络字节序 → 主机字节序。

```c
uint16_t ntohs(uint16_t netshort);
```

16 位网络字节序 → 主机字节序。

端口号是 16 位用 `htons`，IP 地址是 32 位用 `htonl`。

## 字符串与二进制地址互转

IP 地址经常以点分十进制字符串（如 `"192.168.1.1"`）出现，需要转成二进制存入地址结构体：

```c
int inet_aton(const char *cp, struct in_addr *inp);
```

字符串 → 网络字节序的二进制地址。成功返回 1，失败返回 0。

```c
in_addr_t inet_addr(const char *cp);
```

功能同上，但出错返回 `INADDR_NONE`（即 -1）。**有缺陷**：-1 本身是合法地址 `255.255.255.255`，所以优先用 `inet_aton` 或 `inet_pton`。

```c
int inet_pton(int af, const char *src, void *dst);
```

现代推荐的转换函数，`af` 填 `AF_INET`（IPv4）或 `AF_INET6`（IPv6）。成功返回 1，地址错误返回 0，出错返回 -1。

```c
char *inet_ntoa(struct in_addr in);
```

反向转换，二进制 → 字符串。返回的是静态缓冲区，**后续调用会覆盖**，打印前要注意。

# 小结

- 网络按范围分为 PAN / LAN / MAN / WAN。
- 分层把复杂的网络通信拆成职责单一的各层，上层只关心接口，不关心实现。
- 现实网络遵循 TCP/IP 四层模型；数据每向下一层就封装一次（PDU = SDU + PCI）。
- 网络传输统一用大端字节序，编程时用 `htons/htonl/ntohs/ntohl` 在主机序和网络序之间转换。
