# 信号量和线程池

## 信号量

### 基本概念

- 信号量是非负整数变量，用于控制共享资源的访问，解决多个进程或线程之间的互斥和同步问题。
- 信号量用来协调进程或线程的执行，本身不传输数据。
- 信号量本质是一个整数计数器和一个等待队列。
- **整数计数器：代表了资源可用数量，可以理解为“停车场剩余车位”**，值为0代表没有可用数量，也没有人在等；值小于0代表没有可用资源且有对应数量的人在排队等着用。
- 等待队列：**用来记录有哪些进程/线程正在等待这个信号量有可用数量**。即记录每个排队等着的人

### 分类

- 按用途：
  - 二进制信号量：值只能是0或1，作用等同互斥锁，同一时刻只允许一个执行单元进入临界区。
  - 计数信号量：值可以是任意非负整数，表示可用资源数量，用于控制执行顺序，例如消费者必须在生产者发送数据后才能消费。
- 按名称：
  - 无名信号量：通过`sem_t`的内存位置标识，使用前初始化，不用时销毁，设置更快、效率更高，通常用于线程间通信。
  - 有名信号量：通过名称唯一标识，系统范围内可见，可用于任意进程间通信，通常用于进程间通信。
- 可用于进程间通信的方式通常也可以用于线程间通信。

## 无名信号量

### 相关函数

```c
int sem_init(sem_t *sem, int pshared, unsigned int value);
```

在`sem`指向的地址初始化无名信号量。`pshared`为0表示线程间共享，非0表示进程间共享；进程间共享时信号量必须放在共享内存区域（/dev/shm）。`value`为初始值。

```c
int sem_destroy(sem_t *sem);
```

销毁无名信号量。

```c
int sem_post(sem_t *sem);
```

V操作，信号量值加1，即释放掉一个可用资源。如果其他进程或线程正在因值为0而阻塞，V操作可能会唤醒它们。

```c
int sem_wait(sem_t *sem);
```

P操作，信号量值减1，即拿走一个可用资源。若操作前信号量值为0则阻塞等待值变为大于0，然后再减1。

- 相关函数成功返回0，失败返回-1并设置`errno`。

### 作为二进制信号量使用

- 用于线程间通信时，初始值设为1，进入临界区前调用`sem_wait`，退出临界区后调用`sem_post`，作用和使用上和互斥锁相同，即可用数量总共就一份。
- 用于进程间通信时有两个必要条件：
  - `sem_init`的`pshared`必须为非0，否则一个进程`sem_post`释放的信号量无法被其他进程获取，程序会卡死。
  - `sem_t`必须放在共享内存区域（通过`shm_open`、`ftruncate`、`mmap`创建），否则每个进程各自管理自己的信号量，无法同步。
- 父进程和子进程都映射同一个共享内存后，用信号量保护共享变量，两次加一结果正确。

### 作为计数信号量使用

- 计数信号量主要用于控制执行顺序。
- 单缓冲区生产者消费者模型使用两个信号量：`empty`初始值为1，`full`初始值为0。
  - 生产者：`sem_wait(empty)`，写入数据，`sem_post(full)`。
  - 消费者：`sem_wait(full)`，读取数据，`sem_post(empty)`。
- 这样保证消费者必须在生产者发送数据后才能消费，除首次外生产者必须等消费者读完才能继续生产。
- 判断二进制信号量和计数信号量不能只看值是否在0和1之间变化，要看控制效果：二进制信号量起互斥作用，计数信号量起顺序控制作用。
- 计数信号量用于进程间通信时，同样需要把`sem_t`放在共享内存中，`pshared`设为非0。

## 有名信号量

### 相关函数

```c
sem_t *sem_open(const char *name, int oflag, mode_t mode, unsigned int value);
```

```c
sem_t *sem_open(const char *name, int oflag);
```

```c
int sem_close(sem_t *sem);
```

```c
int sem_unlink(const char *name);
```

- 名称形如`/somename`，以`/`开头，之后不能再出现斜线，长度上限为`NAME_MAX - 4`。
- `sem_open`：创建或打开有名信号量。使用`O_CREAT`创建时必须提供权限`mode`和初始值`value`；只打开已存在的信号量时使用两个参数版本。
- 成功返回信号量指针，失败返回`SEM_FAILED`。
- `sem_close`：关闭当前进程对信号量的引用，每个打开过信号量的进程在结束时都应关闭。
- `sem_unlink`：移除有名信号量对象，只有当没有任何进程引用它时才真正清除，只执行一次。

### 使用方式

- 作为二进制信号量：`sem_open`时初始值设为1，用`sem_wait`和`sem_post`保护共享内存中的变量。
- 作为计数信号量：`sem_open`时初始值设为0，子进程执行`sem_post`，父进程执行`sem_wait`，确保父进程在子进程之后执行。
- 有名信号量在`/dev/shm`中有对应文件，文件名是去掉名称开头的`/`后加上`sem.`前缀，例如`/named_sem`对应`sem.named_sem`。

### 总结

- 从编码复杂度和效率考虑，进程间通信用有名信号量，线程间通信用无名信号量。
- 信号量跨进程使用时，要注意共享资源的创建和释放顺序，避免资源泄漏或在错误时机释放资源。
- 关键步骤应检查函数返回值，配合`perror`输出错误信息。

## 线程池

### 简介

- 线程池是管理和重用多个线程的设计模式，避免每次处理任务都创建和销毁线程，减少开销，提高资源利用率。
- 工作流程：
  1. 创建线程池并指定任务函数，线程池按配置立即创建线程或按需创建线程。
  2. 提交任务时，任务数据进入任务队列。
  3. 线程从任务队列取出任务数据，调用任务函数执行；执行完成后继续取下一个任务，没有任务时线程可能被回收。
- 线程池中的所有任务执行的是同一个任务函数，通过任务数据区分不同任务。

### Glib相关数据类型

- `GFunc`是任务函数类型，声明为`void (*GFunc)(gpointer data, gpointer user_data)`。
- `gpointer`是`void *`的别名，`gint`是`int`的别名，`gboolean`是`gint`的别名。
- `GThreadPool`是线程池结构体，保存任务函数、用户数据等信息。
- `GError`用于返回错误信息。

### 相关函数

```c
GThreadPool *g_thread_pool_new(GFunc func, gpointer user_data, gint max_threads, gboolean exclusive, GError **error);
```

```c
gboolean g_thread_pool_push(GThreadPool *pool, gpointer data, GError **error);
```

```c
void g_thread_pool_free(GThreadPool *pool, gboolean immediate, gboolean wait_);
```

- `g_thread_pool_new`：创建线程池。
  - `func`为池中线程执行的任务函数；`user_data`会传给每个任务，不需要时传`NULL`。
  - `max_threads`为可同时运行的线程数，`-1`表示不限制。
  - `exclusive`为`TRUE`时立即启动`max_threads`个线程且只能被当前池使用；为`FALSE`时按需创建线程，且线程可以和其他非独占线程池共用。
  - 无论是否发生错误，都会返回有效的线程池指针。
- `g_thread_pool_push`：向线程池添加任务数据，实际是放入任务队列；有可用线程时立即执行，否则任务在队列中等待。成功返回`TRUE`，失败返回`FALSE`。
- `g_thread_pool_free`：释放线程池资源。
  - `immediate`为`TRUE`时立即释放，未处理的任务数据不再处理；为`FALSE`时等最后一个任务执行完毕。
  - `wait_`为`TRUE`时阻塞直到所有需要处理的任务完成，为`FALSE`时立即返回。
  - 无论参数如何，正在执行的线程不会被中途打断。

### 编译

- Glib库编译时需要用`pkg-config`获取编译和链接标志。
- `pkg-config --cflags glib-2.0`获取头文件搜索路径等编译标志。
- `pkg-config --libs glib-2.0`获取链接标志，例如`-lglib-2.0`表示链接`libglib-2.0.so`。
- 也可以直接使用`pkg-config --cflags --libs glib-2.0`一次获取全部标志。
- 在Shell中，反引号的作用是执行其中的命令，把命令的标准输出作为其他命令的参数，因此可以把`pkg-config`的输出传给gcc作为编译参数。
