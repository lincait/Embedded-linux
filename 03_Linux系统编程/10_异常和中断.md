# 异常和中断

## 内核态和用户态

- **内核态**：CPU的一种运行模式，具有执行所有指令和访问所有硬件资源的权限。操作系统内核在这种模式下执行其核心功能，所有与硬件交互的操作都必须在内核态下执行。由于具有完全的系统控制权，任何在内核态执行的代码都必须是高度可靠的，以避免系统崩溃或安全漏洞。
- **用户态**：CPU的另一种运行模式，权限受限。应用程序在用户态下运行，不能直接执行特权指令或访问受保护的内存区域。用户态为应用程序提供了安全的执行环境，通过系统调用请求操作系统提供的服务。
- **特权指令**：只有在内核态下才可以执行的指令。这些指令提供了对硬件和关键系统资源的直接控制能力，因此被严格限制在操作系统内核中，防止恶意软件或错误的程序代码破坏系统的稳定性和安全性。

## 中断和异常的分类

### 中断

- 中断（Interrupt）通常是I/O设备或时钟触发的，信号来自处理器外部，不是由任何一条指令造成的，从这个角度讲，它是**异步**的。
- 中断处理完毕后总是执行下一条指令。

### 异常

- 异常（Exception）是CPU执行指令时检测到特定条件触发的，x86-64架构定义了三种异常：陷入（Trap）、故障（Fault）和终止（Abort）。
- **陷入**：由进程执行陷入指令（可以切换到内核态的指令）主动触发的，是**同步**的，执行完毕后总是执行下一条指令。系统调用就是通过陷入实现的。
- **故障**：由错误情况引起，可能被故障处理程序修正，如上文提到的缺页故障就是故障的一种。故障发生时，处理器将控制权交给故障处理程序，如果故障被修复，则**返回引起故障的指令并重新执行**；否则处理程序返回到内核中的abort例程，后者终止引起故障的进程。
- **终止**：不可恢复的致命错误造成的结果，如底层硬件错误，或进程产生的算术异常，无法被修复。终止发生时，CPU将控制权交给终止处理程序，这个程序**不会将CPU的控制权返还给应用程序**，而是返回到内核中的abort例程，后者终止进程。
- 理解：陷入像"自己主动打电话求助"（系统调用）；故障像"发现算错账，重算一遍就行"（缺页故障补上页面后重执行该指令）；终止像"账本烧了"，没法补救，直接倒闭（进程被终止）。

### 中断和异常的区别

- 在x86-64架构中，中断处理例程被调用时，CPU会清除EFLAGS寄存器中的IF（Interrupt Enable）位，避免其它中断干扰当前中断处理例程的执行；而异常处理例程被调用时IF不会被清除。

## 中断描述符表（IDT）

- 操作系统为每种中断或异常都分配了唯一的中断向量（Vector），它是一个非负整数。一部分中断向量由CPU的设计者分配（如被零除、缺页、内存访问违例即算术运算溢出等），另一部分由操作系统内核的设计者分配（包括系统调用和来自外部I/O设备的信号）。
- 操作系统启动时，内核会分配和初始化一张称为中断描述符表（IDT）的跳转表，将中断向量和中断或异常处理程序映射。IDT中的每一项（entry）对应一种中断或异常。
- 中断描述符表寄存器（IDTR）指明了IDT的基地址和边界。
- 理解：IDT像"总机电话簿"，每种事件一个分机号（中断向量），拨号（中断号）就能找到对应的处理程序。

## 中断和异常处理

CPU以相同的方式处理中断和异常：当中断或异常发生时，CPU暂停当前程序或任务的执行，通过IDTR定位IDT，通过中断号检索IDT确定处理例程的入口，切换到处理例程，执行完毕后回到被中断的程序或任务。

### 段寄存器

- x86-64架构中，段寄存器（CS、DS、SS、ES、FS和GS）是16位的段选择器。
- 现代Linux系统内存管理的方式是**分页**，早期的操作系统曾经通过**分段**管理内存——分段是将内存空间切分为几个大段，内存模型中的每个部分占据一块。x86-64架构的Linux使用的也是分页，保留段寄存器一方面是为了向前兼容，另一方面是用于存储一些关键的系统状态信息（如特权级信息）。

### TSS

- 任务状态段（Task State Segment，TSS）是x86-64架构中用于支持任务切换和状态管理的数据结构。
- 在早期的操作系统设计中，它被用于实现硬件级的任务切换功能，但在现代操作系统中，主要用于管理**内核栈的切换**。

### 内核栈

- 在x86-64架构下，为每个线程维护一个内核栈，大小为2页（8K），存储在内核空间。
- 内核栈用于在中断或异常处理和CPU调度切换线程时保存当前正在执行的进程的状态，并在内核线程的工作中发挥作用。
- 当线程在用户空间执行时，内核栈中只有`thread_info`对象。

### 中断或异常处理程序的调用流程

1. 临时存储当前CPU寄存器SS、RSP（栈指针）、RFLAGS（状态寄存器）、CS、RIP（程序计数器）等寄存器的值。
2. 从TSS里把段选择器的信息和栈指针加载到SS和ESP寄存器，切换到**内核栈**，并为中断或异常处理例程开辟栈帧，此时切换至**内核态**。
3. 将第一步临时存储的寄存器值压入内核栈。
4. 将error code压入内核栈。注意：error code是硬件层面由CPU自动处理和生成的，与特定的中断或异常关联，包含导致中断或异常的具体原因。它和讲解`perror()`时用到的`errno`是不同的——`errno`是C标准库提供的全局变量。
5. 更新程序计数器，指向中断或异常处理例程。
6. 如果是中断处理例程，清除RFLAGS寄存器中的IF标志位。
7. 在内核态下开始执行中断或异常处理例程。

### 中断或异常处理程序的返回

中断或异常处理程序的返回是通过执行**IRET**指令开始的。要注意，如果触发的是终止（Abort），则不会返回用户进程。

1. 执行权限检查，确保接下来的操作在内核态下进行。
2. 恢复CS和RIP寄存器的值。
3. 恢复RFLAGS寄存器的值。
4. 恢复SS和RSP寄存器的值，内核栈中异常处理程序的栈帧弹栈。栈指针重新指向进程用户空间中的用户栈，由内核态切换到用户态。
5. 在用户态下继续执行被中断的程序。

理解：整个调用和返回过程就像"进办公室办事再出来"——进门（压栈）时登记你的状态（寄存器值），办事（执行处理例程），出门（弹栈）时恢复你的状态，接着干原来的活。内核栈就是进门时"寄存物品的柜子"。

### 中断上文和中断下文

- **中断上文**：异常发生之前处理器的状态，即中断处理时最先压入内核栈的数据，包括段选择器的值、栈指针、程序计数器、状态相关寄存器等的值。
- **中断下文**：涉及中断或异常处理时内核所处的环境和状态，包括内核栈中保存的用户线程状态、状态寄存器、段选择器和内核栈指针等寄存器、内核态下执行的中断或异常处理函数等内容。
- 理解：上文像"出门前家里的状态记录"，下文像"出差期间单位的环境"——下文处理完，按上文恢复家里的状态。

## 案例

### 页表基地址

- 页表负责虚拟地址到物理地址的映射，地址转换首先要找到页表所在的地址。
- x86-64架构实现了**四级页表**，一级页表的地址存储在**CR3寄存器**，这个寄存器的值会被记录在PCB中，在进程切换时会被保存和更新。
- MMU可以访问CR3定位一级页表，然后逐级检索，完成地址转换。

### 缺页故障

- 执行用户代码时，进程工作在用户态，进程访问虚拟内存，MMU首先查询TLB。
- 若TLB命中，则将虚拟地址转换为物理地址，对这块地址执行操作。
- 若TLB未命中，则访问CR3寄存器定位一级页表，多级检索定位页帧，最终将虚拟地址转换为物理地址，继续后续操作。
- 如果查询的虚拟内存页尚未映射到物理页帧，MMU无法在页表中查到相应的PTE，此时触发**缺页故障**（Page Fault），操作系统介入，为虚拟页分配页帧，而后回到触发故障的指令继续执行（这就是前面讲的"故障"异常——修复后重新执行引起故障的指令）。

## 系统调用和库函数

### 系统调用

- 系统调用是操作系统提供的服务接口，允许用户空间的应用程序请求操作系统执行特定的功能，这些功能通常涉及资源管理、文件操作、进程控制等更深层次的系统任务。系统调用是操作系统内核功能的直接接口。
- 用户在程序中执行系统调用，CPU会执行**陷入指令**，切换到内核态，执行相应的异常处理程序，实现用户进程对内核功能的调用。
- 系统调用运行在内核态，具有访问硬件和管理系统资源的权限。涉及用户态到内核态的切换，**执行开销较大**。

### 库函数

- 库函数通常用高级语言编写，存储在函数库中，最常见的是C标准函数库。
- C标准函数库（C Standard Library，简称libc）是由ANSI C标准定义的函数库集合，为C语言程序员提供标准化的程序接口，实现基础的程序功能，如输入输出处理、字符串操作、数学计算等。
- 在现代Linux发行版中，使用最多的libc实现是GNU C函数库，简称glibc，它是GNU项目的一部分。可以用下面的命令查看自己系统的glibc版本：

```bash
/lib/x86-64-linux-gnu/libc.so.6
```

- 库函数运行在用户态，不涉及用户态和内核态的切换，**执行开销较小**。
- 许多库函数在内部使用系统调用实现其功能。
- 理解：库函数像"前台服务台"——你直接跟前台办事（用户态，开销小），但前台处理不了的事（如读写文件）还是得去找后台部门（系统调用）。比如`fopen`是库函数，底层最终调用`open`系统调用；`printf`最终调用`write`系统调用（呼应01笔记）。
