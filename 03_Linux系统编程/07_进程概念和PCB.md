# 计算机系统的软件分层

- 在单片机学习中我们直接用代码和硬件交互，这种方式缺点很明显：复杂度高、细节繁琐（处理底层寄存器和端口配置时极易出错）、出错时调试难度高、更换芯片时往往要重写驱动导致可移植性很差。
- 为了解决这些问题，操作系统应运而生。它在硬件之上做了一层抽象，提供统一的接口和服务，隐藏了硬件的复杂性和差异性，让开发者专注应用逻辑的实现。

## 内核

- 内核是操作系统的核心部分，负责管理计算机的硬件资源，包括处理器、内存、存储设备和其他外围设备。
- 内核提供系统服务的基础，如进程管理、内存管理、设备驱动、文件系统和网络通信等。
- 内核是硬件和应用程序之间的中介，提供一个抽象层，使得应用程序不需要直接与硬件交互。

## 应用程序

- 应用程序是运行在操作系统之上的软件，用于执行特定的任务，如文本编辑、图像处理、网络通信等。
- 应用程序提供用户所需的功能，依赖操作系统提供的接口与硬件资源进行交互。

# 进程和程序

- 程序是存储在硬盘等存储介质的代码，是一串二进制机器码，是**静态的**。
- 进程是正在运行的程序及相关资源的总称，是一种抽象，是**动态的**。

# 进程控制块PCB

内核为了管理进程，会保存每个进程的一些信息，称为**进程控制块**（Process Control Block，PCB），主要内容如下：

- 进程编号（PID）：每个进程对应的唯一编号，一般为正整数形式。
- 进程状态信息。
- 进程切换时需要保存和恢复的一些CPU寄存器，其中关键的是程序计数器的值，用于记录进程恢复时应执行的指令地址。
- 内存管理信息，如页表、内存限制、段表等。
- 当前工作目录。
- 进程调度信息，包括进程优先级、调度队列指针等。
- I/O状态信息，包括分配给进程的I/O设备列表、打开的文件描述符表等。文件描述符表里有很多指向`struct file`结构体的指针。
- 同步和通信信息，包括信号量、信号等用于进程同步和通信机制的信息。
- 用户id和组id。

理解：PCB就像每个进程的"户籍档案"，内核靠它知道每个进程是谁（PID）、现在是什么状态、干到哪一步了（程序计数器）、占用了哪些资源。进程的一切都记录在这里，所以内核要管理进程只需要管好PCB。

# Linux的PCB：task_struct

在Linux内核中，进程控制块的实现是结构体`task_struct`，上述信息都存储在这个结构体中。它定义在`include/linux/sched.h`头文件中，主要字段如下：

```c
struct task_struct {
    struct thread_info thread_info;	// 执行环境的必要信息
    ......
    void *stack;			// 内核栈
    ......
    unsigned int flags;			// 标志位信息
    ......
    struct fs_struct *fs;		// 文件系统信息
    ......
    struct mm_struct *mm;		// 内存管理信息（包含指向内存区描述符的指针）
    ......
    struct files_struct *files;		// 包含指向打开的文件描述符表的指针
    ......
    pid_t pid;				// 进程ID
    pid_t tgid;				// 线程组ID
    ......
    const struct cred *real_cred;	// 真正的证书，包含用户和用户组的信息
    const struct cred *cred;		// 当前有效的证书
    ......
    struct signal_struct *signal;	// 与信号处理相关的信息
    struct sighand_struct *sighand;	// 与信号处理函数相关的信息
};
```

- `mm`字段指向的`mm_struct`就是进程的内存管理信息，即页表相关的内容（后面08笔记展开）。
- `files`字段指向的`files_struct`就是打开的文件描述符表，01笔记里讲的文件描述符就存在这里。
- `pid`和`tgid`字段的区别在12笔记（进程和线程）中展开：`pid`表示进程或线程ID，`tgid`表示线程组ID。
- `cred`里存的就是PCB中的用户id和组id。
